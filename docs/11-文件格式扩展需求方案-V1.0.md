# 11-文件格式扩展需求方案 V1.0（2026-10-16）

> 本文 = 开发目标 = 验收标准。与 06-调研-文件格式扩展.md 冲突以本文为准。
> 用户已口头确认两条关键决策：① Excel 双形态切片；② 一期不装 LibreOffice，.doc 拒收提示另存。

## 1. 范围

### FR-01 支持格式 5 → 13 种
| 类别 | 格式 | 解析路径 |
|---|---|---|
| 已有 | .pdf .docx .txt .md .markdown | 不动 |
| 表格 | .xlsx .xlsm | openpyxl |
| 老表格 | .xls | xlrd 2.x |
| 表格 | .csv | pandas（utf-8/gbk 自动探测） |
| 演示 | .pptx | python-pptx 逐页文本框+表格 |
| 图片 | .jpg .jpeg .png .bmp .webp | 复用现有 qwen OCR 管道（router 加 image 分支） |

### FR-02 拒收清单（明确报错 + 指路，不静默失败）
.doc / .wps / .et / .ofd / .zip / .rar → 400 + 文案：
- .doc → "老版 Word 格式暂不支持，请用 WPS 另存为 .docx 后上传"
- .wps/.et → "WPS 私有格式请另存为 .docx/.xlsx 后上传"
- .zip/.rar → "压缩包不支持，请解包后逐个上传（每个文件需单独设定密级）"

### FR-03 Excel 双形态切片（本需求核心难点）
对每个 sheet 先做形态判断（纯规则：抽样统计平均单元格字符数）：
- **数据表型**（平均 <20 字）：每 20 行一个 chunk，**每个 chunk 头部重复表头行**；chunk 前缀 `【文件名 · sheet名】`
- **文档型**（平均 ≥50 字）：逐行句子化拼接成连续正文（`表头列名：单元格内容`），再走现有 300-500 字滑窗切块
- **混合**：前部连续长文本区(≥2 行长文本行)先按文档型切，剩余表体按数据表型切；阈值之间(20-50)默认数据表型
- 合并单元格：取左上值填充整个合并区域（openpyxl 需 unmerge 处理）
- 空行/空 sheet：跳过，不产生 chunk

### FR-04 熔断线（防 OOM / 防成本失控）
| 项 | 上限 | 超限行为 |
|---|---|---|
| 单 sheet 行数 | 50,000 | 拒收，提示"请拆分后上传" |
| 单 workbook sheet 数 | 50 | 只解析前 50 个，任务标记 partial 原因 |
| 单 PPT 页数 | 200 | 拒收提示拆分 |
| 图片单张 | 20MB | 拒收（现有大小限制内） |
| OCR | 图片走现有逐页限额 | 同现有 scanned_pdf 策略 |

### FR-05 密级/ACL 全程不变
新格式与老格式走同一套：上传必过密级弹窗、build_doc_acl 写侧唯一构造器、检索强制 build_acl_filter。本需求**不触碰** P1 权限层任何代码。

### FR-06 前端同步
dropzone 文案改"支持 PDF/DOCX/PPT/XLSX/XLS/CSV/TXT/MD/图片"；`accept` 属性扩全列表；拒收错误文案直接展示后端 detail。

## 2. 不做（明确排除）
- 不装 LibreOffice（.doc 一期拒收；正式资料真出现大量 .doc 再启用 06 号调研 C 方案）
- 不引入 MarkItDown / Docling / MinerU
- 不做行转句 LLM 增强（规则句子化已够）
- 不做批量导入界面（那是 P2 另一半，本需求只扩格式）
- 表格内公式不求值（openpyxl data_only=True 取缓存值，取不到当空）

## 3. 依赖与环境
- pip：openpyxl、xlrd、pandas、python-pptx（合计 ~60MB，新增常驻内存 <100MB）
- 磁盘增量 <200MB；不新增任何系统级服务/守护进程

## 4. 验收标准（测试对齐此表）
1. 四种表格样例（数据表型 xlsx / 文档型 xlsx / 混合 / 老 .xls / gbk 编码 csv）入库后，按行检索命中且 chunk 内含表头
2. pptx 提取文本+表格，逐页可引用
3. 一张制度照片(jpg) OCR 入库可检索（走 qwen 管道）
4. .doc/.wps/.zip 上传 → 400 + 指路文案逐条断言
5. 超限行数/页数熔断 → 明确报错不是 500
6. 新格式文档同样受 L1-L4 ACL 隔离（复用现有 33 条测试 + 新增用例全过）
7. 空 sheet、纯格式 sheet（无数据）不产生 chunk、不报错
8. 合并单元格值正确展开
