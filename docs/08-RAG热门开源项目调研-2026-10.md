## 二、三条主线趋势（结论先行）

1. **深度文档理解成为胜负手**。RAGFlow 80k 的核心原因是 DeepDoc：版面分析、OCR、表格识别做成引擎内置，1.0 起全部 CPU 推理（无 GPU 也能跑，与我们轻量服务器匹配）；并且"切块结果可视化 + 人工干预修正"是官方卖点。**行业共识 = Garbage in garbage out，解析层解决质量，检索层解决精度。**
2. **图谱 RAG 分化：微软 GraphRAG 退潮，LightRAG 上车**。2026 年 GraphRAG 索引成本从约 $33k 降到接近向量 RAG 平价（cruxdigits 2026 决策框架文），但官方仓库月提交仅 3；LightRAG 靠"双层检索 + 增量更新不重建图"成为活跃主流。**对我们的含义：若上 wiki/图谱精化层（V2 方案 §3.6），实现候选应加 LightRAG，增量更新特性正好适配"知识库持续有部门上传"的场景——GraphRAG 全量重建模式在这种场景是灾难。**
3. **Agentic RAG 成为新默认叙事，但要警惕**。Dify/FastGPT/RAGFlow 全部往 agent 模板靠。多方对比（ByteByteGo、CruxDigits、Medium 对比文）的一致结论：agentic 检索更准但更慢更贵更难调试——**适合"多跳推理问题"，不适合"员工查制度原文"这种一次检索就够的场景**。我们 V2 的问答形态（单跳+权限过滤）不该被带节奏加 agent loop；招投标"AI 拆查询→多路召回"已经是轻量 agentic，够用。

## 三、逐项详研：对我们 V2 方案的具体影响

### 3.1 RAGFlow —— 必须正面回答"为什么不直接用/不用它改造"

- 强项恰好是 V2 的 P2/P3 痛点：扫描件深度解析（版面+表格+OCR）、切块可视化人工修正、引用溯源展示。这些我们自己已经手搓了同类件（docling/qwen-vl-ocr/双hash门禁/页码引用），**质量路线一致，说明方向没赌错**。
- 弱项恰好是 V2 的 P0 根基：**权限模型**。RAGFlow 开源版是 dataset/团队级共享粒度（企业版才补 RBAC，且开源版功能边界随版本变），**没有"chunk 携带 ACL、按钉钉部门动态过滤召回"这种组织级权限**——这正是我们方案 §3.4 的核心。我们若拿它当引擎，等于把整个检索链换成别人的，再在自己手里重写权限层（比现在改 rag-cs 更伤筋动骨）。
- 决策建议：**不整体替换；偷它的交互**。两处直接抄进 V2 设计：①上传后"切块预览+人工干预"页（我们 §1.3 步骤 6 已有雏形，RAGFlow 做得更完整：可直接编辑 chunk 文本再入库，值得升级规格）②答案引用可跳转到原文高亮位置。另：DeepDoc 单独拆用理论上可行（infini-tools 有独立解析能力），但引入它的解析链=同时接管其 chunk schema，与我们 gate 机制冲突，性价比低，暂不。
- ⚠️ 诚实标注：RAGFlow 企业版权限细节未逐条核官方文档（开源/企业功能边界易变），如老板想认真评估"换引擎"路线，需要单独做一次 POC 级核查。

### 3.2 Dify / FastGPT / MaxKB —— 平台三件套的启示

- 共同形态：知识库只是平台的一个模块，主打可视化编排。对我们没有架构价值（我们是单一场景垂直系统），有价值的是**产品交付形态**：MaxKB 的"开箱即用企业知识库+嵌入第三方"证明这种产品客户接受度靠部署省事，不靠检索极限。
- 不采用。V2 不是平台，是带权限的垂直问答系统。

### 3.3 LightRAG / GraphRAG / nano-graphrag —— wiki 二期（§3.6）的实现候选更新

- 原方案里 wiki 层是"LLM 改写+双索引"自研思路。LightRAG 的双层检索（low-level 实体/high-level 主题）+ **增量插入**，可视为 wiki 精化的现成实现。风险同样是权限：LightRAG 图谱节点没有 ACL 概念，跨部门文档进同一张图=权限打穿（§3.6 写过的坑在第三方实现里更严重，因为它默认全库构图）。
- 结论不变（二期、条件触发），但实现候选清单加 LightRAG；**若用，必须按部门分图实例**（每部门一套 workspace），不做全局图——这条写进 V2 §3.6 修订。

### 3.4 all-in-rag（Datawhale）/ RAG_Techniques —— 学习材料，不动工程

- datawhalechina/all-in-rag 中文 RAG 全栈教程，star 增长快；RAG_Techniques 我们此前已在用。维持学习资源定位。

## 五、一句话给老板

火的那批项目验证了我们的两条判断：**解析质量是知识库生死线**（RAGFlow 靠这个 80k star）、**重方案在退潮轻增量在上车**（GraphRAG 凉 vs LightRAG 火）；唯一需要认真对抗的问题是"为什么不直接用 RAGFlow"——答案是权限模型（chunk 级 ACL + 钉钉组织动态过滤）开源项目全都没有，这恰好是 V2 要自建的那一层，也是这个项目对外包/对甲方真正的护城河。
